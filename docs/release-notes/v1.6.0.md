# Kassandra v1.6.0 release notes

## Highlights

- **Choose where Kassandra keeps its configuration.** Besides JSON files, connections, favorites, saved queries and
  column metadata can now live in **SQLite**, **PostgreSQL**, **MySQL / MariaDB** or **Firebase (Firestore)**, so a
  team can share one configuration. Pick the backend under *Storage* on the Configuration page, or fix it for a
  deployment with `KASSANDRA_STORAGE` (`file`, `sqlite`, `postgres`, `mysql`, `firestore`) and the matching
  `KASSANDRA_SQLITE_PATH`, `KASSANDRA_DB_URL` / `KASSANDRA_DB_SCHEMA` or `KASSANDRA_FIRESTORE_*` variables. Switching
  copies the current configuration into an empty target. Database passwords and service-account keys are stored in a
  mode-0600 file on the server and are never sent back to the browser.
- **Configuration page and first-run setup.** On first start Kassandra asks where to keep its configuration; the gear
  icon at the bottom of the sidebar reopens the page. It also holds the new **Appearance** setting.
- **Light, Dark and System appearance.**
- **Docker Compose profiles.** `docker compose --profile file|sqlite|postgres|mysql|firestore up --build` starts
  Kassandra and Cassandra with the chosen configuration backend, starting the database or Firestore emulator when needed.
  Configuration storage is temporary unless you set `KASSANDRA_DATA`, `POSTGRES_DATA` or `MYSQL_DATA` to a local folder.
  **Note:** a plain `docker compose up` now starts only Cassandra, and the old persistent `kassandra-data` volume is no
  longer used.
- **Keyspace and table selectors from the keyboard.** `Cmd/Ctrl+D` opens the keyspace selector and `Cmd/Ctrl+T` the
  table selector (`Option/Alt+K` and `Option/Alt+T` for browsers such as Safari that reserve them). Deleting the row in
  Row detail is now `Option/Alt+D` only, so `Ctrl+D` no longer conflicts.

## Also in this release

- **Generate CQL in the data grid.** Next to **Apply**, sends a `SELECT` with the applied filters to the CQL editor.
- **Format CQL.** Next to **Save query**, reformats the editor text and upper-cases keywords.
- **Import schema.** On the Table Schema tab, copy column metadata from another table's file, after confirmation.
- **Version and What's new** link at the bottom of the sidebar.
- **Per-table metadata files.** Column metadata moves out of `config.json` into one document per connection and table.

## Upgrading

On the first start, Kassandra migrates a 1.5.0 configuration automatically: it backs up everything to
`backups/1.5.0/`, then moves `table_metadata` out of `config.json` into per-table files, copying it to every existing
connection. Configuration is locked during the migration so processes sharing one storage cannot migrate at once.

See the [user guide](../index.md) for instructions.
